# 719 瓶与检验操作

inventory.json是明确初始业务日10的小输入，没有已有库存数据库。种类R的L=2，所有份数为整数，日期为整数日。operations.json按非递减日执行；reserve_competition让两个独立连接使用不同运行ID争同一LAST瓶，胜者不预定。

U总4份，入库10，预留时不设开封。12日reserve-U开始才开封并消耗1；新版方法M/v2随后消耗2，所以剩余未占1、预留0、消耗3。13日这1份可领；14日因开封12+2到期，当日可领0，但未占仍为1，守恒不能丢掉过期份数。

P总2份、开封9，10日预留1，11日开始过期失败：未占回到2、预留0、消耗0、当日可领0。LAST的一次成功预留仍不设开封，另一运行失败不占身份或数量。方法修订只作用于新运行；重复开始reserve-U不能再扣1。操作文件不要求强杀、分布式恢复或真实仪器。

## 容器退押（`deposit_inventory.json` / `deposit_operations.json`）

以上 719 只覆盖库存与运行；退押场景是独立的模拟库存（包装号、押金、规格、运费均为虚构账务数据）：

- A、B 同型同供应商，各押 4、交还日 12。A 10 日经普通运行耗尽；B 的 1 份因印刷到期（第 12 天）不可领但仍在瓶里。C 为另一种小瓶型，D 是未动用的 R 瓶。
- A、B 两瓶合寄最优：12 日到车，两格箱费 5，`8 − 5 = 3`。只有 A 时 `4 − 5 < 0`，最优不寄；车改 13 日到则两张单都不寄（过交还日不付押金）。
- B 的过期未占份须由两名不同盘点员对同一盘点版本、同一准确份数签字清退后才可申请凭单；两人签不同版本则停在 `pending`。
- 过期前被旧 holder 预留、过期时仍 `active` 的瓶，清退与凭单都被阻断。

`demo_deposit.py` 跑完把装车与守恒结果写入 `deposit_results.json`；其中也验证车改 13 日、异版本签字、旧 holder 占用三个分支。守恒始终为 `total = unallocated + reserved + consumed + cleared`，`cleared` 单列，绝不伪装成 `consumed`。
